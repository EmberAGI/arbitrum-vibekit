Proposed architecture decision · EMB-1148

Deterministic plugin registry snapshots

Load and validate plugin sources once, then publish one read-only snapshot for the process lifecycle.

Context

Mutable arrays and deferred promises currently make discovery depend on which consumer iterates first.

The server duplicates this behavior and copies yielded plugins into another registry.

Decision

The public registry becomes the owner of source loading, global identity validation, and immutable snapshot publication.

Protocol initializers become explicit sources instead of hardcoded generic-registry behavior.

Trade-offs

AlternativeWhy rejected
Continue lazy iterator mutationReader order remains observable and duplicate registration remains possible.
Let every consumer cache independentlyLifecycle, errors, and ordering drift across consumers.
Use a general capability bag for actions and dataWeakens domain typing and conflates transaction generation with read evidence.

Consequences

  • Readiness waits for required sources and validation.
  • Optional failures must have an explicit degraded-state contract.
  • Consumers migrate from ownership of loading to consumption of the published snapshot.
  • Registry package CI must test lifecycle and concurrency semantics.

Domain contract · EMB-1148

Public plugin registry snapshots

Plugin discovery publishes one deterministic, validated snapshot instead of exposing mutable arrays and iterator side effects.

Intended behavior

Plugin sources

Protocol factories, local sources, and deferred imports.

→
Load phase

Resolve with explicit timeout and failure behavior.

→
Validation

Unique IDs, supported types, and lifecycle ownership.

→
RegistrySnapshot

Read-only identities and deterministic ordering for every consumer.

Domain concepts

Plugin source

An explicit factory or loader that can produce zero or more action/query plugins.

Registry snapshot

The stable ordered plugin set published after load and validation.

Deferred load

An asynchronous plugin source whose success and failure policy is part of the interface.

Lifecycle capability

Refreshable topology owned by one stable plugin/provider ID.

Rules and invariants

  • One plugin ID identifies exactly one plugin in a published snapshot.
  • Source order and plugin ordering are deterministic and documented.
  • Repeated reads return the same snapshot without resolving, registering, or duplicating plugins again.
  • Duplicate IDs, unsupported types, and lifecycle ownership conflicts fail validation.
  • The generic registry accepts explicit sources and does not hardcode Aave or another protocol initializer.
  • Deferred source timeout and failure behavior are explicit rather than iterator-dependent.
  • Lifecycle capabilities cannot silently overwrite another owner.
  • Market-data providers remain outside the DeFi action/query PluginType model.

Interfaces/contracts

InterfaceResponsibility
PluginSourceStable source ID and an explicit asynchronous load operation.
PluginSourceResultLoaded plugins plus safe warnings for skipped or failed optional sources.
RegistrySnapshotVersion, creation time, ordered read-only plugins, lifecycle capabilities, and source results.
Registry initializationLoad sources once, validate globally, then publish or fail readiness.
Compatibility seamExisting iteration consumers receive an explicit migration path backed by the stable snapshot.

Load-state map

Loading

No incomplete mutable plugin set is published.

Ready

One validated snapshot is available to every reader.

Degraded

Only explicitly optional source failures may publish with structured warnings.

Failed

Required-source, duplicate-ID, or lifecycle conflicts prevent publication.

Edge cases

  • The same plugin ID from two sources is an error even when the implementations appear identical.
  • A deferred plugin that resolves after timeout cannot mutate an already published snapshot.
  • A source returning no plugins is distinguishable from a source failure.
  • Multiple consumers can read concurrently without triggering multiple load cycles.

Constraints

  • Existing plugin action/query typing remains supported during migration.
  • The registry package gains substantive contract tests; a no-op CI command is insufficient.
  • Public diagnostics contain no RPC credentials or raw provider exceptions.

Non-goals

  • No server wrapper migration; EMB-1149 consumes this contract.
  • No market-data adapter or provider-catalog implementation.
  • No external-data evidence DTO redesign; EMB-1145 owns it.
  • No protocol action semantics change.
